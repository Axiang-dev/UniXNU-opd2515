Diagnostic change
-----------------
- S9 enables only entry_probe_reset_delay = 6 in the host board configuration.
- The reset cave is placed at 0xFFFFFFF0073FA4A0 when panic-screen output and the
  reset probe are both enabled, so it does not overlap PANIC_CAVE_END.
- The no-reset regression kernel is byte-identical to the S8 payload kernel:
  E810A2E36F4113CABAF02028B9DD816E7D337CD538F40FC6D11DDA92C5FDBA38.
- The S9 kernel differs from the S8 payload kernel by 64 bytes.
- Disassembly shows the original mov x0, #0x300000 followed by a CNTPCT_EL0 wait
  for six seconds and a PSCI SYSTEM_RESET call with function ID 0x84000009.

Checks completed
----------------
- S9 payload readback matched the host-built kernel byte for byte.
- unixnu.toml, ADT, v2 trust cache and DarwinBoot match the S8 payload byte for byte.
- The Android boot header, EFI segment and payload segment passed readback.
- No S9 image was booted on hardware. MMU completion and kernel C-path progress
  remain unproved until a device run shows the expected six-second reset timing.

Device acceptance
-----------------
Green, blue and magenta must still appear. A reset about six seconds after the
magenta checkpoint proves the MMU-enable instruction executed and stage 3 was
reached. An earlier reset does not prove stage 3; no reset after six seconds
means CPU did not reach the configured reset checkpoint.
